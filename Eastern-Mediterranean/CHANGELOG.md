# Changelog

All notable changes to AnthracoForm – Eastern Mediterranean (Lebanon), formerly Lebanon, are documented here.
This project follows simple incremental versioning; v0.x are pre-release builds,
to be promoted to v1.0 once validated on real assemblages.

## [v0.7] - 2026-11-01

### Added
- Morphology: **pith**, after twig (column `pith`): 1 = pith present on the fragment, 0 = not present. Shown on the PDF record sheet and counted in the taxon and type reports
- Morphology: **reaction wood**, after bark (column `reaction_wood`): 1 = reaction wood on the fragment (eccentric growth; in softwoods, thick-walled tracheids with oblique striations), 0 = not present. Shown on the PDF record sheet and counted in the taxon and type reports
- Taphonomy: **fungal hyphae**, after xylophagous activity (column `fungal_hyphae`): 1 = fungal hyphae seen, empty = not seen or not recorded (never 0), like the other alterations. Listed in the Taphonomy tab of the SU summary (Biological, with xylophagous activity) and in the PDF reports

### Changed
- CSV schema v1.5: 223 columns (44 descriptive), with `pith` after `twig`, `reaction_wood` after `bark` and `fungal_hyphae` after `xylophagous_activity`. CSV files saved with earlier versions import unchanged; the three columns are added, empty (not recorded), at the next save. Data dictionary: S1 v1.5

## [v0.6] - 2026-10-30

### Added
- Diagnostic IAWA features, coded as in the p/a/r/e searches of InsideWood (present, absent, required present, required absent): a **D** box at the right of each feature marks it as diagnostic. CSV coding of the IAWA columns: empty = not assessed, 0 = absent, 1 = present, 2 = required present (present and diagnostic), 3 = required absent (absent and diagnostic). A feature is diagnostic only in relation to the taxa it separates: the mark records the features that decided the identification of that fragment. Clicking D on an untouched feature records it in the current mode (present or absent) and marks it as diagnostic; clearing a feature removes the mark. In the N_iawa boxes a diagnostic feature is written with `*` (`5*`) and can be typed in the same way. Counters and PDF reports show the diagnostic features (★)
- Help mode (**💡 Help**, file bar): a short explanation for new users appears when the mouse rests on any element of the form (fields, buttons, channels, IAWA features, panels). On by default; switched off with the same button, and the choice is remembered by the browser. The welcome window explains it
- Compare: the lists also offer the provisional types of the open file (`tipo_n`). The profile of a type is calculated from its fragments each time the tab is opened (features present, 1 or 2, in at least 50% of the fragments of the type in which they were assessed), so it grows with every fragment recorded
- PDF reports: **📄 PDF Report** opens a window with three choices: this record, all the fragments of a taxon, all the fragments of a provisional type. Every report is made of A4 pages that are always filled: the photographs take the space left by the text, and the text is reduced when it does not fit. Taxon and type reports: number of fragments, sites, SU, channels, fractions, taphonomy, morphology, operators, IAWA profile (share of the fragments in which each feature was assessed that have it present, diagnostic records) and the list of fragments, followed by **all** the photographs of the taxon or type from the photo folder (6 on the first page, then 12 per page, with fragment, SU and file name). Photographs are reduced to 1400 px on the long side to keep the PDF light
- IAWA codes can be typed in the two N_iawa boxes (green: present, red: absent), as numbers separated by a space (`1 4 6`; `;` and commas also accepted), and applied with Enter, which rewrites them in the format of the list generated by the clicks (`1; 4; 6;`) or by leaving the box: the features are marked in the checklists as if clicked and their section is ticked. Deleting a number clears the feature; a code in both boxes counts in the box edited last; numbers not in the list of the wood type are not applied and stay in the box, marked in red. No ranges. Esc cancels
- The CSV file that is opened is overwritten at each save and keeps its name. The file bar shows the time of the last save and the operator who saved it (`Last saved: 12:25 by Stefania`); date and operator are also recorded in every row (`date`, `operator`)
- "Magnification" field under Microscope: the magnifications used, free text; it can be kept with KEEP like operator and microscope (column `magnification`). Shown on the PDF record sheet. The lower part of the form now reads Microscope, Magnification, Operator
- "📷 Photo folder" button in the file bar (Chrome, Edge): the folder of the photographs, the same for the whole project, as in a GIS project. Chosen once, it is remembered by the browser and connected automatically when the form is opened (if the browser keeps the permission, e.g. "Allow on every visit" in Chrome/Edge; otherwise the browser asks at the first click on the page); the button only chooses or changes the folder. The photos of each record are shown again whenever the record is opened. With the folder connected, "＋ load" opens it and the photo names are saved relative to it (subfolders with "/"); photos outside the folder are not added. If the folder is moved or renamed, it is chosen again with the same button
- Several photographs per section: `photo_trv`, `photo_tan` and `photo_rad` hold the file names separated by "; ". Each photo can be removed from the record with ✕ (the file is not deleted); the PDF record sheet shows all of them. Any file name can be used; the title of the photo panel recalls the naming of our laboratory (SITE_SU_CHANNEL_SECTION_ID_n, e.g. MGL_SU11_HC_RAD_ID032_1)
- Taphonomy: "other alteration" field under vitrification, free text (several alterations separated by ";"), saved in the new column `other_alteration`. The alterations already recorded in the file are listed under the field and added with a click, as for the taxa under the determination field. Shown on the PDF record sheet
- IAWA features are recorded as present (1), absent (0) or left empty (not assessed). A switch above the three section panels (✓ Present / ✗ Absent, `Alt+A`) sets what a click records; clicking a marked feature again clears it; untouched features stay empty. "All others absent" records every untouched feature of a section as absent, "Clear" empties the section. The panels have a red border in Absent mode; the mode returns to Present after each save
- Hovering over an IAWA code shown as a number only (IAWA Reverse Lookup: selected codes and the matching / absent in taxon / in taxon, not checked lists; Dichotomous Key: IAWA codes of the result) shows the description of the feature

### Changed
- Saturation panel: the curve of the current fragment is drawn on the left (HF+LF of the unit; CDC for DS, TDC for HC), with the horizontal axis up to the next step, new taxa as open circles and the steps as dashed lines; a click opens the full curve. The figures are on the right, with a line on the fragments left to the next step. The panel now stands to the right of the identification and type rows; the identification field takes the whole width, so the list of taxa takes fewer lines
- Form layout: less space between the rows of wood type, channel, fraction and fracture type
- Unit of the cumulative curves: the SU, or the SU and context when the context is filled in. SU 60 and SU 60 · context 1 are two curves, each with HF and LF together; the CDC (DS, with its HF+LF seed), the saturation panel and the SU summary (all tabs) follow the same unit, chosen in their windows as "60" or "60 · 1". The saturation panel follows the SU and context in the form
- Notes: no example text in the field
- Photo card title shortened: "📷 TRV - TAN - RAD (SITE_SU_CHANNEL_SECTION_ID_n - e.g. MGL_SU11_HC_RAD_ID032_1)"
- File bar: "Open CSV" opens the system file dialog to choose the CSV file itself (before: the folder that contains it); "New CSV" creates a new file with the save dialog. Both dialogs reopen in the last folder used
- Text 40% larger throughout the form and the windows (the PDF record sheet is unchanged); fixed-width columns widened to match
- CSV: IAWA columns are 0, 1, 2, 3 or empty (before: 1 or 0); 2 and 3 mark diagnostic features (see Added). The columns of the feature list that does not apply to the wood type are empty. A 0 is written only if a section where the feature is visible is ticked in "Observed sections". CSV files saved with earlier versions import unchanged; their IAWA and taphonomy 0 values meant "not ticked" and must be corrected by hand (empty where not a real absence)
- Taphonomy columns: 1 (alteration seen) or empty (not recorded), no longer 0: an alteration not seen may be present but not visible. Summary, Taphonomy tab: share of the fragments of the SU on which each alteration was seen
- "Observed sections" follow the IAWA features: clicking a feature ticks its section, and a section left without any feature recorded (present or absent) is unticked. Unticking a section by hand clears the features visible only in sections not observed. Sections not observed are dimmed
- CSV schema: 220 columns (41 descriptive), with `other_alteration` after `vitrification` and `magnification` after `microscope`. CSV files saved with earlier versions import unchanged; the columns are added, empty, at the next save
- N_iawa, the section counters and the PDF record sheet list present and absent features separately
- IAWA list, TRV, Parenchyma: feature 88 now comes before 89. The CSV columns follow (`iawa_A88` before `iawa_A89`, as in the data dictionary S1); CSV files saved with earlier versions are read by column name and import unchanged
- Taxa recorded at genus and species level only: the 11 subspecies and varieties in the reference database, taxa dictionary and dichotomous key (`db`) now carry the species name (*Abies nordmanniana*, *Acer cappadocicum*, *A. heldreichii*, *Crataegus azarolus*, *Erica sicula*, *Fraxinus angustifolia*, *Hippocrepis emerus*, *Pinus nigra*, *Quercus infectoria*, *Q. macranthera*, *Q. petraea*). IAWA profiles and key couplets unchanged; the duplicate dictionary entry of *Pinus nigra* removed

### Removed
- `curv_sat` field (sat. curv.) and CSV column: the cumulative number of taxa can be read on the curves, which follow the unit chosen (220 columns instead of 221). CSV files saved with earlier versions still import; their `curv_sat` column is dropped at the next save. The TDC, CDC and 📊 buttons stay in the same place, under "curves"
- `layer` field: removed from the form, the KEEP bar, the record card, the curve titles (TDC, CDC, SU summary) and the CSV schema (219 columns instead of 220). CSV files saved with earlier versions still import; their `layer` column is dropped at the next save

### Fixed
- Nomenclature checked against POWO (Plants of the World Online, accessed 2026-10-20). Renamed in the reference database, taxa dictionary and dichotomous key (`det` and `db`); IAWA profiles and key couplets unchanged:
  - Synonyms: *Acer divergens* → *A. cappadocicum* subsp. *divergens*; *Acer trautvetteri* → *A. heldreichii* subsp. *trautvetteri*; *Crataegus aronia* → *C. azarolus* var. *aronia*; *Erica verticillata* Forssk. → *E. manipuliflora*; *Erica bocquetti* → *E. sicula* subsp. *bocquetii*; *Pyrus serikensis* → *P. boissieriana*; *Quercus infectoria boissieri* → *Q. infectoria* subsp. *veneris*; *Rosa dumalis* subsp. *boissieri* → *R. boissieri*
  - New genus: *Coronilla emerus emeroides* → *Hippocrepis emerus* subsp. *emeroides*; *Inula heterolepis* → *Pentanema verbascifolium*; *Rosmarinus officinalis* → *Salvia rosmarinus*; *Sorbus torminalis* → *Aria torminalis*. The genus-level results of the key follow: *Hippocrepis* sp., *Hippocrepis*/*Gonocytisus* type, *Pentanema* sp., *Salvia* sp., *Aria* sp. (formerly *Coronilla* sp., *Coronilla*/*Gonocytisus* type, *Inula* sp., *Rosmarinus* sp., *Sorbus* sp.)
  - Spelling: *Rhamnus hirtella*, *R. nitida*, *R. pyrella*, *R. thymifolia* (*Rhamnus* is feminine); *Fontanesia philliraeoides*; rank written out in *Quercus macranthera* subsp. *syspirensis* and *Q. petraea* subsp. *pinnatiloba*

## [v0.5.1] - 2026-10-10

Dichotomous Key checked against the original pages of Akkemik & Yaman (2012, pp. 293–296).

### Added
- Saturation panel next to the determination fields, always visible: one row for each of the three curves — HF+LF of the SU (saturation curve), DS of the SU (CDC) and HC of the site (TDC) — with number of taxa and number of fragments on the curve, shown against the next step (100, 200, 250, 300, 400) with a bar coloured grey, amber from 50 and green from 100; the last step reached is marked (e.g. "→200 ✓100"). 100 is a minimum on the arid-zone assemblages of Sindh and Iranian Sistan; 200–400 follow the sample sizes in Kabukcu & Chabal (2021). The row of the channel being recorded is highlighted; STR and C14 have no curve. The panel follows the SU, site and channel in the form (when the SU is empty, those of the last record)
- Curve windows (saturation, TDC, CDC, summary): dashed lines at the steps reached, and the number of fragments left out of the curve

### Changed
- Cumulative curves (saturation curve, `curv_sat`, SU summary, TDC, CDC) follow Kabukcu & Chabal (2021): only fragments with a taxon are on the curve. Indeterminate fragments, *cf.* determinations and determinations with "/" (e.g. *Senegalia/Prosopis* type) are recorded as before but are no longer counted as fragments of the curve (before they counted as fragments, not as taxa); `curv_sat` is empty for them. The curves are computed by one function
- KEEP row, channel: more than one channel can be ticked at the same time. The channel of a record passes to the next record if it is ticked (tick HF, LF, DS and HC and the channel always carries over); with a single channel ticked, the next record starts with that channel, as before. Ticking a channel no longer changes the channel of the current record, unless it has none

### Fixed
- Section C, couplets 14–16 as in the book (p. 295): couplet 14 "Vessels solitary and/or in radial multiples" / "All vessels in dendritic pattern"; couplet 15 "All vessels mostly in radial multiples" (→ 16: *Nerium* / *Olea*) / "Vessels solitary and/or in radial multiples" (→ 17). Before, couplet 14 carried the text of couplet 15, and couplets 15 and 16 were merged into one three-way couplet. The results do not change.
- Gymnosperms: "in earlywood" restored in the cross-field pitting couplets (G2, G2a.1); couplet G2a is labelled as the *Pinus* step, as in the book.

### Removed
- The stop criterion "no new taxon in 50 consecutive fragments" and its line on the curves: the plateau of an accumulation curve has no mathematically defined end point (Kabukcu & Chabal 2021); the panel and the curves show the steps on the number of fragments instead
- The warnings "check against the original" on the Picea/Pinus block and on couplets 15–16 of section C.
- The yellow "new taxon" note under the determination field (it read "new taxon → update saturation curve"): the saturation panel replaces it

## [v0.5] - 2026-10-08

### Added
- Open CSV: in browsers without folder access (File System Access API) an existing file can be opened from disk and saved with Download CSV; the file bar shows whether there are changes not yet downloaded, and the browser warns before closing the page if there are
- `tipo_resolved` column: when a provisional morphological type is resolved, the type is kept in this column (with its description in `tipo_desc`) instead of being lost; the form shows "resolved from tipo_n"

### Fixed
- Interface text left in Italian now in English: file bar ("No folder selected", "Last saved"), photo placeholders ("load TRV photo", ...), message when a taxon is added to the taxa dictionary, tooltips of the morphology dots and of the taxa list
- SU summary, Taphonomy tab: the subtitle no longer refers to the old 1–3 scale ("% presence over fragments where it was recorded")
- Notes written on several lines broke the record into two when the file was read again (Reload CSV or a new session); the CSV reader now keeps line breaks inside quoted values
- Download CSV quotes values that contain a line break
- Resolve dialog title in English

### Changed
- Module renamed **Eastern Mediterranean (Lebanon)** (formerly Lebanon), file `AnthracoForm_Eastern-Mediterranean.html`: module names follow floristic regions (Loidi & Vynokurov 2024), and the place in brackets is where the reference collection was made. Page title and header read "AnthracoForm – Eastern Mediterranean (Lebanon)"; the header title wraps on narrow screens
- Column `ossidation` renamed `oxidation` (CSV schema v1.3, 220 columns). Files written with earlier versions are converted on load and rewritten in the new schema at the first save
- SU summary: Richness, Simpson and Ecology use HF and LF fragments only, the channels that share a known volume; taxa found only in other channels are listed under the Richness chart
- Taxa dictionary: where the reference database (mostly Turkish material) and the present-day vegetation of Lebanon disagree, the Lebanese vegetation takes precedence. *Quercus* sp.: maquis and pine woodland (was deciduous woodland; *Q. calliprinos* is the dominant oak in Lebanon). *Pyrus* sp.: deciduous woodland, as *P. syriaca*, the Lebanese species (was empty)

## [v0.4] - 2026-10-07

### Added
- Source of the reference database: Akkemik, Ü. & Yaman, B. (2012). *Wood Anatomy of Eastern Mediterranean Species*. Verlag Kessel (badge in IAWA Reverse Lookup; cited under Compare Taxa)
- Sources: sampling of present-day vegetation and creation of the reference collection (I. Minervini)
- Dichotomous Key tab: key to genera of Akkemik & Yaman (2012, pp. 293–296), from the transcription, in English — gymnosperms and angiosperms (sections A–C by perforation plates); each result lists the reference-database species of that genus. The Picea/Pinus block and couplets 15–16 of section C are flagged in the tab, to be checked against the original
- Taxa dictionary (auto-fill of family and ecology): the 93 species of the reference database, with the ecology validated on 7 October 2026; the determinations given by the Dichotomous Key and the genera of the database (*Genus* sp.), with the family shared by their species and the most frequent ecology among them — ecology left empty only where the species are evenly split (*Buxus*, *Pyrus*, *Rosa*, *Coronilla*/*Gonocytisus* type)
- Taxa dictionary: the eight genera the key reaches that have no species in the reference database — *Celtis*, *Tilia* and *Ulmus* (deciduous woodland), *Daphne*, *Ephedra* and *Styrax* (maquis and pine woodland), *Salix*/*Populus* and *Tamarix* (riverine). Their ecology comes from the distribution of the genus in Lebanon and the Levant, not from the reference database.
- Ecological categories of the module in the ecological composition chart: maquis and pine woodland, deciduous woodland, mountain forest, riverine, other

### Changed
- IAWA Reverse Lookup as in the Sindh module: results sorted by, and showing only, % covered
- A determination with *cf.* no longer adds a taxon to the cumulative curves (saturation curves, `curv_sat`, SU summary, TDC, CDC); the fragment itself is still counted
- PDF record sheet: html2canvas 1.4.1 and jsPDF 2.5.1 (both MIT) are embedded in the file instead of being downloaded from a CDN, so the tool never uses the internet
- Same code as the Sindh module: the regional data (module name, sources, ecological categories, taxa dictionary, reference database, dichotomous key) are in the REGIONAL MODULE DATA block at the top of the file, and the rest of the file is identical in the two modules
- CSV files with numeric IAWA columns (`iawa_1`, ..., module v0.1) are converted on load to `iawa_A1`, ... with wood type angiosperm, as in the Sindh module

### Fixed
- Moving between records (arrows, search by id_det or SU) no longer re-saves a record that was not edited: the form is written back only if something changed after the record was loaded.
- Label of IAWA feature A141 (IAWA Committee 1989): "prismatic crystals in non-chambered axial parenchyma cells"; it showed the definition of feature 140.
- Alt+←/→ works from any tab (it switches to the Form) and warns when no records are loaded

### Removed
- Compare Taxa: "powered by Claude" from the empty screen; the tool is offline and uses no AI

## [v0.2] - 2026-09-23

### Changed
